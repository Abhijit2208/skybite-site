1. Summary

SkyBite is a prototype that links a passenger's dietary needs to the meals an airline can actually serve, from booking to the seat tray. Indian dietary needs combine religion (Jain, sattvic, fasting, halal), region, health and personal choice, and they often change late. SkyBite treats a late request as a normal event with a defined path to a safe meal.

  • Passenger screen: set food needs and allergies, chat with the SkyBite assistant, read the ingredients of every meal, and order up to three meals.
  • Cabin crew screen: receives orders live, re-checks each meal against the passenger's rules ("Do not serve" if a check fails), shows stock, and can request more.
  • Menu planner: the airline adds special meals; demand and crew restock requests appear live; the occasion calendar is shown as a locked table.
  • Occasion meals: festival meals (Navratri, Diwali, Eid, Christmas) appear by calendar date; birthday and anniversary meals are always available.

2. How it works

Safety design

  • A deterministic rule engine decides whether a meal suits a passenger. It checks ingredient flags and a listed-allergen vocabulary (peanut, tree nut, dairy, egg, gluten, soy, sesame, fish, shellfish, mustard).
  • The AI assistant only converts free text into structured needs (diet, rules, allergens). It never decides safety, never names meals as safe, and the passenger can edit everything it fills in.
  • An allergy the vocabulary does not cover is shown as unverified, and the crew screen flags it for confirmation.
  • Allergen and religious rules are never relaxed to find a faster option.

Substitution ladder for late requests

StepOption
1Planned meal that fits the profile
2Compatible meal from buffer stock
3Premium alternative that satisfies every rule
4Hot meal from the lounge or a sealed airport pack, only if there is time
5Recovery: safe snack, apology, and a record for the next flight

The ladder is implemented in the Python prototype (skybite.py) and the earlier demo page. The live ordering app uses the rule engine and stock counts; it does not run the full ladder.

Demand buffer

Spare special meals per flight = a chosen quantile of a negative-binomial distribution of late requests (passengers x late-request rate x festival uplift). Synthetic simulation of 20,000 flights (assumed 1.2% late-request rate, +60% in festival periods): on large festival-period flights the dynamic buffer cut the share of flights with a shortfall from 20.1% to 9.9% against a fixed buffer of 6 (8 vs 6 meals loaded). Averaged over all flights a well-tuned fixed buffer performed about the same (6.1% vs 7.0% shortfall). These numbers come from synthetic data and are not airline results.

Technology

Single-file web pages (HTML, CSS, JavaScript). Live sync uses claude.ai's shared storage; the assistant uses Claude through the page runtime with a keyword fallback. A Python file (skybite.py) holds the rule engine, ladder, buffer calculation and self-tests.

6. Limitations and assumptions

  • Prototype only: no airline systems, real recipes or real passengers are connected; all data is synthetic.
  • Ingredient flags and allergen lists were entered by hand. A wrong flag gives a wrong suggestion, so real use needs caterer recipe data and supplier verification.
  • Nutrition values are illustrative; a real system would take them from recipes and an Indian food composition table.
  • Jain, vrat and sattvic practices vary by community; the rules use common definitions.
  • Buffer results are from a simulation with assumed rates and must be re-fitted on real history.
  • The live app has no sign-in of its own: anyone with edit access to the shared link can place or change orders.
  • Live sync and the Claude-powered chat work only on claude.ai; elsewhere the page runs in single-device mode with a keyword matcher.
  • Camera-based nutrition scanning is not built; it was judged unreliable for safety decisions.
